# DCE 11.0 (Carrizo) vs DCE 11.2 (Polaris) register diff

A register-by-register comparison of the Linux headers `dce_11_0_{d,sh_mask}.h` and `dce_11_2_{d,sh_mask}.h`,
done to find which writes from Apple's `AMD9500Controller` (written for DCE 11.2) would land correctly on
Carrizo's DCE 11.0 and which would not.

- Source: `torvalds/linux` master @ `47324d3a5b3a`, `drivers/gpu/drm/amd/include/asic_reg/dce/`.
- Generated by [`scripts/dce_regdiff.py`](../scripts/dce_regdiff.py). Every difference is in
  [`data/dce11_0_vs_11_2.csv`](data/dce11_0_vs_11_2.csv), so you can look up any offset seen in Ghidra.
- Offsets are **dword indices** into the MMIO BAR (multiply by 4 for the byte offset), as in Linux.
- Companion to [CARRIZO_VS_POLARIS.md](CARRIZO_VS_POLARIS.md) rows 6–7.

## Result in one paragraph

**The display pipeline itself is the same.** CRTC timing, GRPH surface/flip, cursor, scaler, line buffer,
gamma/CSC, FMT, DIG encoders, DP, HDMI info frames, HPD, AUX, I²C, watermarks, VGA, backlight and DAC are all at
identical offsets, with only a few bit-field differences (below). What differs is the **clock and PHY hardware**:
the pixel PLLs at 0x1700–0x177D and the PHY block at 0x4800–0x49FF are different designs that reuse the same
address ranges. Linux drives both through VBIOS command tables rather than writing those registers. If Apple
does the same, Carrizo's own VBIOS handles them, and our work moves to *how* the VBIOS tables are called (see
"Pixel clock" below).

## Where the two really differ

### 1. Pixel PLLs: 0x1700–0x177D (high impact)

| | DCE 11.0 (Carrizo) | DCE 11.2 (Polaris) |
|---|---|---|
| Design | Integer/fractional divider PLL ×3 (`BPHYC_PLL0..2`) | New "PPLL" ×3 (`DC_DISPLAYPLLREGS0..2`) |
| Registers | `PLL_REF_DIV` 0x1700, `PLL_FB_DIV` 0x1701, `PLL_POST_DIV` 0x1702, `PLL_SS_AMOUNT_DSFRAC` 0x1703, `PLL_SS_CNTL` 0x1704, `PLL_DS_CNTL` 0x1705, `PLL_IDCLK_CNTL` 0x1706, `PLL_CNTL` 0x1707, `PLL_ANALOG` 0x1708, … | `PPLL_VREG_CFG` 0x1700, `PPLL_MODE_CNTL` 0x1701, `PPLL_FREQ_CTRL0..3` 0x1702–0x1705, `PPLL_BW_CTRL_COARSE` 0x1706, … |
| Plus | Per-PHY PLL registers inside each UNIPHY (`UNIPHY_PLL_*`) | 6 combo-PHY PLLs (`DC_COMBOPHYPLLREGS*`) |
| DC clock sources | `PLL0`, `PLL1`, `EXTERNAL` | `COMBO_PHY_PLL0..5`, `DP_DTO` |

Every offset in this window means something different on the two chips (96 collisions). For example, a Polaris
write to `PPLL_MODE_CNTL` (0x1701) lands on Carrizo's `PLL_FB_DIV`.

**Pixel clock.** Linux doesn't touch these registers for mode sets. Both generations call the VBIOS
`SetPixelClock` table (`dce_clock_source.c`), but **with different inputs**:

| | `dce110_program_pix_clk` (Carrizo) | `dce112_program_pix_clk` (Polaris) |
|---|---|---|
| Driver computes dividers | **Yes**: reference, feedback, fractional feedback, post divider (`dce110_get_pix_clk_dividers`) | No: passes only the target pixel clock |
| Spread spectrum | Driver disables before / enables after (non-DP) | Handled by VBIOS |
| Flags | `SET_EXTERNAL_REF_DIV_SRC` | `SET_GENLOCK_REF_DIV_SRC`, `SET_XTALIN_REF_SRC`, `SUPPORT_YUV_420` |
| Resync after | `PIXCLK{0,1,2}_RESYNC_CNTL` (0x13A/0x138/0x139) | `PHYPLL{A..F}_PIXCLK_RESYNC_CNTL` (0x100–0x103, 0x10C, 0x13E) |

So the `SetPixelClock` parameter struct revision is different (newer VBIOS computes the dividers itself). If
Apple fills in the Polaris-style struct, Carrizo's VBIOS will get zeros for the dividers.
**Fix:** hook Apple's pixel-clock call, compute the dividers ourselves (port `dce110_get_pix_clk_dividers` and
its PLL calculator, MIT-licensed), and call the table revision Carrizo's VBIOS implements. Check which
`SetPixelClock` revision the A12-9800's VFCT image contains.

**Resync:** Polaris's resync writes to 0x100–0x103/0x10C hit nothing on Carrizo (deep colour wouldn't be set up).
The write to 0x13E lands on Carrizo's `PHYPLL_PIXCLK_CNTL`, so it **must be blocked or redirected**.

### 2. PHYs: 0x4800–0x49FF (high impact if Apple writes them, none if it uses VBIOS)

- Carrizo: classic UNIPHY ×9 (`BPHYC_UNIPHY0..8`: 0x48C0 + 0x20·n for 0–6, then 0x49C0 and 0x49E0), each with
  `UNIPHY_TX_CONTROL1–4`, `UNIPHY_POWER_CONTROL`, `UNIPHY_PLL_FBDIV/CONTROL1/2/SS_*`, `UNIPHY_TPG_*`, and so on.
- Polaris: combo PHY (`DC_COMBOPHYCMREGS*`, `DC_COMBOPHYTXREGS*`, `DC_COMBOPHYPLLREGS*`, `DCIO_UNIPHY*` macro
  "reserved" registers) over the same range.
- 632 of the 730 collisions are here.

Linux DC enables/disables links and sets lane drive through `bios->funcs->transmitter_control`
(`dce_link_encoder.c`), so it never writes these registers. **In Ghidra: confirm Apple also calls the VBIOS
`DIGxTransmitterControl` / `UNIPHYTransmitterControl` table** and doesn't write PHY registers directly (for
example, for DP link-training voltage swing / pre-emphasis). Any direct write found in this range must be
blocked.

### 3. Other collisions (outside the PLL/PHY ranges)

| 11.2 register | Offset | Lands on (11.0) | Notes |
|---|---|---|---|
| `PHYPLLF_PIXCLK_RESYNC_CNTL` | 0x13E | `PHYPLL_PIXCLK_CNTL` | Pixel-clock resync, see above. Block. |
| `DMIFV_STATUS` | 0x2F5 | `DMIF_ADDR_CONFIG` | Underlay DMIF status on 11.2. Apple has no reason to use the underlay, but a write here would change Carrizo's DMIF address config. |

### 4. Registers only on Carrizo (Apple won't program them)

| Registers | Why it matters |
|---|---|
| `PLL_*`, `BPHYC_PLL*`, `PPLL_SPARE*`, `PPLL_STATUS_DEBUG`, `DISPPLL_BG_CNTL` | The classic PLL block (§1) |
| `UNIPHY_*`, `BPHYC_UNIPHY*` | The classic PHYs (§2) |
| `PIXCLK{1,2}_RESYNC_CNTL`, `PHYPLL_PIXCLK_CNTL` | Deep-colour resync; we program these instead of Apple |
| `DVMM_PTE_ARB_CONTROL`, `DCP{n}_DVMM_PTE_ARB_CONTROL`, `UNP_DVMM_PTE_*` | **Display VM**. DCE 11.0 can scan out of GART/system memory ("DCE SG support" in `gmc_v8_0.c`). Not needed if the framebuffer is in the carve-out. |
| `DMIF_ADDR_CONFIG` | DMIF's view of the memory address layout. Probably needs to match `GB_ADDR_CONFIG` (2 pipes). Check what Linux/the VBIOS leaves in it on hardware. |
| `CRTCV_*`, `DPGV*`, `DCFEV{n}_*` | Underlay (video overlay) pipe. Apple has no use for it. |
| `DP_AUXn_AUX_GTC_SYNC_*` | DP Global Time Code. Not used by Apple. |
| `SYMCLKG_CLOCK_ENABLE`, `FBC_IDLE_MASK` | Minor. |

### 5. Registers only on Polaris that Apple may write

Apart from the combo-PHY and PPLL sets above (and new underlay/colour-manager blocks Apple won't use):

| Registers | Offset | On Carrizo |
|---|---|---|
| `CRTC{n}_CRTC_EXT_TIMING_SYNC_*` | 0x1BE1–0x1BE6 (+CRTC stride) | Unused offsets. Writes do nothing. |
| `CRTC{n}_PHYPLL_PIXEL_RATE_CNTL` | 0x143 | Unused |
| `DCFE{n}_DCFE_FLUSH`, `DCP{n}_DCP_RANDOM_SEEDS` | 0x1B07, 0x1A61 | Unused |
| `FMT_MEMORY0..5_CONTROL`, `FMT_420_HBLANK_EARLY_START`, `FMT_SIDE_BY_SIDE_STEREO_CONTROL` | 0x1888–0x188D, 0x1BF1, 0x1BF0 | Unused (4:2:0 / stereo) |
| `DC_GPIO_AUX_CTRL_*`, `DC_GPIO_HPD_CTRL_*`, `DC_GPIO_RECEIVER_EN*`, `DC_GPIO_I2S_SPDIF_*`, `DC_GPIO_TX12_EN` | 0x48A0–0x48B2 | Unused. **But** Carrizo AUX/HPD pads may need configuring some other way. If AUX/HPD don't work, look here first. |
| `DCO_PSP_INTERRUPT_*`, `DCO_GENERIC_INTERRUPT_*`, `DCO_HDMI_RXSTATUS_TIMER_CONTROL` | 0x1883–0x1887 | Unused (HDCP/PSP) |
| `DCI_MEM_PWR_CNTL4`, `DCI_MEM_PWR_STATUS3`, `DCPG_INTERRUPT_CONTROL2`, `DMCU_INTERRUPT_STATUS_1` | 0x33B, 0x33D, 0x2E0, 0x1633 | Unused |

Writes to unused offsets are normally ignored by the hardware, so these are low risk. They're listed so a hang
or a missing feature can be traced quickly.

### 6. Same register, different bit fields (the ones that matter)

| Register | Field | 11.0 mask | 11.2 mask | Impact |
|---|---|---|---|---|
| `LB_MEMORY_CTRL` | `LB_MEMORY_SIZE` | 0xFFF | 0x1FFF | Polaris has a bigger line buffer. A size > 4095 truncates on Carrizo, giving scaler/LB corruption at high resolutions. Clamp it. |
| `LB_MEMORY_SIZE_STATUS` | `LB_MEMORY_SIZE_STATUS` | 0xFFF | 0x1FFF | Same (read). |
| `LB_DATA_FORMAT` | `PREFILL_EN` | — | 0x100 | New bit, ignored. |
| `DPG_WATERMARK_MASK_CONTROL` | `URGENCY_WATERMARK_MASK` / `STUTTER_EXIT_SELF_REFRESH_WATERMARK_MASK` / `NB_PSTATE_CHANGE_WATERMARK_MASK` | 2 bits | 3 bits | Watermark set select. If Apple selects set ≥ 4 it aliases on Carrizo. Watermarks need recalculating for DDR4 anyway (DC `dce110` bandwidth code). |
| `DPG_PIPE_NB_PSTATE_CHANGE_CONTROL` | `NB_PSTATE_CHANGE_WATERMARK` | 0xFFFF0000 | 0xFFFF8000 | Bit 15 is new in 11.2. |
| `DMIF_CONTROL` | `DMIF_FORCE_TOTAL_REQ_BURST_SIZE`, `DMIF_MAX_TOTAL_OUTSTANDING_CHUNK_REQUESTS` | 4 / 6 bits | 5 / 6 bits (shifted) | **The field moved** (0x3F0000 → 0x7E0000). Apple's value lands one bit off. Rewrite it. |
| `DMIF_CONTROL` | `DMIF_PSTATE_URGENT_DISABLE` | — | 0x80000000 | New bit. |
| `DMIF_STATUS` | `DMIF_MC_SEND_ON_IDLE`, `DMIF_CLEAR_MC_SEND_ON_IDLE` | 8 bits | 6 bits | Narrower on 11.2, so Apple's values fit. Ignore. |
| `DCI_SOFT_RESET` | `DMIFARB_SOFT_RESET` | 0x1000 | 0x4000 | **Moved.** Apple's DMIF-arbiter reset misses on Carrizo, and bit 12 (11.2 `DCFEV1_L`) goes unused. Translate it if Apple uses this. |
| `DCFE_CLOCK_CONTROL` | bit 17 | `DISPCLK_G_DCP_LOW_POWER_GATE_DISABLE` | `DISPCLK_G_PIPE_REQUEST_DIS_GATE_DISABLE` | Different meaning, same bit. Clock gating, so leave it disabled. |
| `DCFE_SOFT_RESET` | `DCP_LOW_POWER_SOFT_RESET` | 0x40 | — | 11.0 only. |
| `FMT_CONTROL` | `FMT_PIXEL_ENCODING` / `FMT_SUBSAMPLING_MODE` / `FMT_SUBSAMPLING_ORDER` | 0x10000 / 0x20000 / 0x40000 | 0x30000 / 0xC0000 / 0x100000 | Moved for 4:2:0. Fine for RGB output (all zero). Translate if YCbCr output is ever used. |
| `DC_I2C_TRANSACTION0..3`, `DC_I2C_DATA` | `DC_I2C_COUNTn`, `DC_I2C_INDEX` | 8 bits | 10 bits | Transactions > 255 bytes don't fit on Carrizo. EDID blocks are 128 bytes, so it's fine unless Apple reads 256+ bytes at once. |
| `AFMT_AVI_INFO0/1` | `AFMT_AVI_INFO_Y` / `AFMT_AVI_INFO_VIC` | 2 / 7 bits | 3 / 8 bits | HDMI 2.0 VICs (> 127) and 4:2:0 don't fit. Carrizo is HDMI 1.4, so its VBIOS mode list won't include them. |
| `PHY_AUX_CNTL` | `AUX_PAD_RXSEL` | 1 bit | 2 bits | Plus new `AUX_PAD_COMPSEL` / `RESBIASEN`. Check if DP AUX fails. |
| `CRTC_STATIC_SCREEN_CONTROL` | `CRTC_STATIC_SCREEN_OVERRIDE(_VALUE)` | — | bits 30–31 | New, ignored. |
| `CRTCn_PIXEL_RATE_CNTL` | `CRTCn_DISPOUT_HALF_RATE_EN` | — | 0x800 | New, ignored. |
| `CUR_CONTROL` | `CURSOR_BUSY_START_LINE_POSITION` | — | 0xF000 | New, ignored. |
| `DCCG_DS_CNTL` | `DCCG_DS_REF_SRC` | — | 0x30 | Deep-sleep reference source, new. |
| `SCLV_MODE` | `SCL_MODE`, `SCL_MODE_C` | 1 bit | 2 bits | Underlay only. |
| `DMCU_*` (11 regs) | underlay/DCFEV interrupt bits | | | DMCU interrupt routing moved for the second underlay. Matters only if Apple uses the DMCU (check in Ghidra). |
| `DC_GPIO_*_MASK` (13 regs) | pad mask bits | | | Pad differences, follow up only if a GPIO-based feature (HPD, DDC) fails. |
| `FBC_*`, `WB_EC_CONFIG`, `DCI_CLK_CNTL`, `DCI_MEM_PWR_STATUS`, `DCPG_INTERRUPT_STATUS`, `RBBMIF_*`, `SMU_CONTROL` | | | | FBC / writeback / gating, which Apple shouldn't need. |

The CSV has every field difference with full masks.

## What to do with this

1. **In Ghidra (Phase 2), work out how `AMD9500Controller` sets the pixel clock and enables links.** Look for
   AtomBIOS command-table calls (`SetPixelClock`, `DIGxTransmitterControl`, `SetDCEClock`) versus direct MMIO
   writes in 0x1700–0x177D and 0x4800–0x49FF. This decides most of the display work.
2. **Pixel clock hook:** compute Carrizo dividers (port DC's `dce110_get_pix_clk_dividers` + PLL calculator),
   handle spread spectrum like `dce110_program_pix_clk`, call the right `SetPixelClock` revision, and program
   `PIXCLKn_RESYNC_CNTL` instead of `PHYPLLx_PIXCLK_RESYNC_CNTL`.
3. **Register write filter (debug aid):** an MMIO-write hook in the controller that logs, and optionally drops
   or redirects, writes to the collision ranges and the moved fields above (`DMIF_CONTROL`, `DCI_SOFT_RESET`,
   `LB_MEMORY_CTRL`, 0x13E). Cheap to build once we find Apple's register write helper, and it turns silent
   corruption into log lines.
4. **Limit to 3 pipes / 2 PLLs + external** (from [CARRIZO_VS_POLARIS.md](CARRIZO_VS_POLARIS.md) §6–7).
5. **Watermarks and DMIF** need DDR4-appropriate values. Port from DC's `dce110` bandwidth calculations if
   Apple's GDDR5-based numbers cause underflow (flickering or horizontal tearing).

## Regenerating

```sh
python3 scripts/dce_regdiff.py <linux>/drivers/gpu/drm/amd/include/asic_reg/dce \
    --csv docs/data/dce11_0_vs_11_2.csv --out /tmp/dce_diff.txt
```

`--a` / `--b` choose other header sets (e.g. `--b dce_10_0` for Tonga/Fiji comparisons).
